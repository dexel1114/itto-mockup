# ITTO モックアップガイド

## 目的

掲載会社への営業と投資家への説明で、利用者ごとの情報の見え方と、一棟不動産の販売がどの順番で進むかを確認する画面見本です。`spec/12-gamen-list.md` の全画面へ、最初の利用者選択または各ホームの画面一覧から移動できます。

## ファイルと画面の対応

| ファイル | 担当する内容 |
|---|---|
| `index.html` | C-01 利用者選択・デモ入口と、全画面共通の上部・下部 |
| `styles.css` | 全画面の配色、配置、パソコン・スマートフォン表示 |
| `app.js` | C-02〜C-03、B-01〜B-08、S-01〜S-06、A-01〜A-08、O-01〜O-05の表示、固定データ、画面切り替え |
| `.github/workflows/pages.yml` | GitHub Pagesによる画面見本の公開設定 |

画面を1ページずつ別ファイルにせず、利用者の立場と画面番号に応じて表示を切り替えています。これは、`index.html` を開くだけで全画面を見られ、営業中に立場を素早く切り替えられるようにするためです。

公開ページは、変更がメインの保存先へ取り込まれたときに公開機能を有効にして自動更新されます。事業責任者がファイルをダウンロードしたり、GitHub側で公開機能を事前設定したりせず、ブラウザ上で画面確認できるようにするためです。

## 主な画面の役割と設計意図

- **利用者選択：** 買主・売主・仲介会社・ITTO運営の情報範囲を混同せず説明する入口です。
- **物件詳細：** 販売段階、物件概要、公開資料、現在価格を一画面で確認します。買主に公開しない個人情報は見本データにも含めません。
- **オファー入力：** 確定した価格・資金・融資・時期・希望条件を並べ、オファー期間中に成約しないことを明記しています。
- **入札・監視：** 入札中と障害停止中の見え方を同じ情報構造で比較できます。停止時の残り時間から再開する方針を表示します。
- **条件比較：** 買主を匿名番号で示し、落札価格だけでなく資金方法や決済時期を横並びで比較します。落札者を自動指名しないことも明記しています。
- **販売履歴：** オファー、入札、落札、優先交渉、成約を時系列で分け、落札と成約が別の出来事であることを示します。
- **各立場の補助画面：** 審査、通知、問い合わせ、資料、内部コメントなどは、一覧と状態表示によって情報の範囲を確認できます。実際の送信や外部サービス連携は行いません。

## 操作できる範囲

- 利用者の立場、各画面、物件詳細を切り替えられます。
- 入力欄や選択肢を操作し、確認ボタンを押せます。
- ボタン操作後は、実処理をしないデモであることを画面右下に表示します。
- データは再読み込みすると初期状態に戻ります。

## 仮置きした箇所

確定していない具体値や外部サービス名は画面に置いていません。本番開発まで保留されている以下の項目は、状態だけを表現しています。

| 保留事項 | モックアップでの表現 |
|---|---|
| 本人確認・通知の外部サービス | 「審査待ち」「承認済み」「通知済み」などの状態だけを表示 |
| データの保存期間 | 履歴は表示するが、保存期限や削除日は表示しない |
| 1ファイルの容量上限 | 見本ファイルの容量は表示するが、上限値や警告は表示しない |
| 同時利用者数・障害当番 | 停止状態と再開予定の案内だけを表示 |

したがって、未確定仕様を推測した「※仮」の機能はありません。物件名、価格、所在地、日時、会社名などの営業説明用データはすべて架空です。
