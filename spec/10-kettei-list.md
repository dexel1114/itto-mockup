# ITTO MVP 要件一覧

## この文書の目的

この文書は、`spec/02-kettei-jikou.md` のうち**【確定】とされた内容だけ**を、画面設計と将来の開発会社への発注に使える要件として整理したものです。

**確認状況：** 2026年7月31日、事業責任者が本書の販売の流れを確認し、この内容で進めることを了承しました。

- 検討中に却下された案は含めません。
- 本番開発まで保留する事項は、確定要件と混同しないよう末尾に分けています。
- 「落札」と「成約」は別の出来事として扱います。詳しい定義は `spec/13-yougo.md` を参照してください。

## 1. サービスの範囲と利用者

### 1-1. ITTOが提供する範囲

- ITTOは、物件情報の掲載、オファー、入札、優先交渉する買主の選択、履歴保存の場を提供する。
- 売買条件の最終調整、仲介、契約、決済は仲介会社が行う。
- ITTOは仲介、契約、決済を行わない。
- 今回作るものは営業・説明用の見た目だけのモックアップであり、実際の本人確認、通知、入札、契約、決済は動かさない。

### 1-2. 利用者と主な役割

| 利用者 | できること |
|---|---|
| 買主 | 物件の閲覧、掲載仲介会社への問い合わせ、定型オファー、入札、即決、優先交渉への回答 |
| 売主 | 掲載内容の確認、オファー・入札条件の比較、優先交渉する買主の選択、内部コメントの閲覧 |
| 仲介会社 | 物件情報・写真・資料の登録と変更、問い合わせ対応、内部コメントの投稿、成約結果の登録 |
| ITTO運営 | 買主と仲介会社の審査、運営状況の確認、内部コメントの閲覧、障害時の案内 |

## 2. 販売の流れ

物件1件につき、次の順番で進める。オファーとオークションは同時進行させない。

1. 物件を掲載し、販売を予告する。
2. 約1か月のオファー期間を設ける。買主はオファーを提出し、内覧、融資相談、資金計画を進める。この期間中に成約はしない。
3. 最高オファー額を開始価格としてオークションを始める。
4. 開始から24時間は入札だけを受け付ける。
5. 24時間経過後、条件を満たす場合は即決価格を公開し、即決も受け付ける。
6. オークションの結果を「落札」または「不成立」として記録する。
7. 売主が価格と条件を比較し、優先交渉する買主を選ぶ。
8. 契約・決済はサイト外で仲介会社が進める。
9. 契約・決済の完了後、仲介会社が成約結果を登録する。

## 3. 物件掲載と資料

### 3-1. 登録と確認

- 物件情報、写真、資料を登録・変更できるのは仲介会社だけとする。
- 売主は掲載内容を確認できるが、自分では変更しない。
- 物件登録は手入力を前提とし、レインズなどから物件情報を自動取得しない。

### 3-2. 買主に掲載する資料

- 物件写真、販売図面、登記資料、物件調査資料を掲載する。
- 買主全員に見せない個人情報などは、公開前に仲介会社が見えない状態にする。
- 写真は1物件30枚までとする。
- 資料は、販売図面・登記資料・物件調査資料などの各種類につき10ファイルまでとする。
- 仲介会社はオークション開始前まで写真・資料を差し替えられる。
- オークション開始後は、買主の判断材料を変えないため差し替えできない。

## 4. 会員審査と匿名表示

### 4-1. 買主の審査

- 買主は会員登録時に審査する。
- 承認された買主だけがオファーと入札を行える。

### 4-2. 仲介会社の審査

- ITTO運営が宅地建物取引業の免許と会社情報を確認する。
- 承認された仲介会社だけが物件を掲載できる。

### 4-3. 名前の表示範囲

- 買主は優先交渉に選ばれるまで匿名で表示する。
- 売主はすべての買主に対して匿名で表示する。
- 優先交渉に選ばれた後は、その後の連絡に必要な範囲で買主情報を共有する。

## 5. オファー

### 5-1. 位置づけと表示

- オファーは、オークション前に需要を確認するための購入意向とする。オファー期間中に売買は成立しない。
- 買主には自分のオファー内容だけを表示し、他人の内容や金額は表示しない。
- 他人の内容を伏せたまま、「オファー済み ○件」と総件数だけを買主に表示する。
- 融資状況は自己申告とし、審査結果書類の登録機能は作らない。

### 5-2. 入力項目

| 項目 | 入力方法・選択肢 |
|---|---|
| 購入希望価格 | 金額入力 |
| 資金方法 | 現金／住宅ローン／投資用ローン／法人融資／その他から1つ |
| 融資状況 | 事前審査済み／審査中／これから相談／融資不要から1つ |
| 契約・決済時期 | 最短で可能／1か月以内／2か月以内／3か月以内／売主に合わせるから1つ |
| 希望条件 | 現況渡しで可／契約不適合責任免責で可／境界非明示で可／残置物ありで可／賃貸中のままで可／建物未登記でも検討可／その他から複数選択可 |
| 自由記入欄 | 任意。建物利用、改修、引渡し時期、買い替え特約などの補足 |

### 5-3. 開始価格への反映

- オファー期間中に提出された最高オファー額を、そのままオークションの開始価格にする。

## 6. オークションと即決

- オークション開始から24時間は入札だけを受け付ける。
- 即決価格は、物件の出品時に売主が設定する。
- 開始から24時間が経過した時点で、即決を利用できるようにし、即決価格を公開する。
- ただし、24時間経過時点の最高入札額が即決価格以上の場合は、即決価格を公開せずにオークションを続ける。
- 即決が行われた場合も、その時点で決まるのは「落札」であり「成約」ではない。

### 6-1. 障害発生時

- 障害が起きた時点の状態でオークションを一時停止する。
- 復旧後、停止時に残っていた時間から再開する。
- 停止中は、参加者へ停止中であることと再開予定を知らせる。

## 7. 条件比較と優先交渉

- 売主は価格だけでなく、資金方法、融資状況、契約・決済時期、希望条件を比較して優先交渉する買主を選ぶ。
- 売主が「優先交渉に進む」を選ぶと、指名された買主へ通知する。
- 買主は通知時刻から48時間以内に「交渉を進める」または「辞退する」を選ぶ。土日祝も時間に含める。
- ボタンによる回答がないまま48時間を過ぎた場合は失効とする。通知を読んだだけでは回答とみなさない。
- 失効した場合は次点へ自動で移さず、売主が残った候補から選び直す。
- 優先交渉後の条件調整は、電話、メール、既存の電子契約サービスなど、サイト外で行う。
- カウンターオファー専用機能は作らず、必要な補足は既存の自由記入欄または連絡手段で扱う。

## 8. 問い合わせと内部コメント

### 8-1. 物件の問い合わせ

- 売主・買主は、サイト内から掲載仲介会社へ直接問い合わせる。
- 問い合わせは物件の確認に使い、オファー提出や優先交渉後の条件調整には使わない。
- 問い合わせ窓口は、関係者用の内部コメントとは分ける。

### 8-2. 内部コメント

- 内部コメントを書き込めるのは仲介会社だけとする。
- 売主とITTO運営は閲覧できるが、書き込めない。
- 買主は閲覧も書き込みもできない。買主への連絡は定型通知で行う。

## 9. 履歴と成約結果

- オファー、入札、落札、成約の履歴を保存する。
- 落札記録はオークション終了時に記録し、落札者、落札価格、日時を含める。
- 成約結果は契約・決済の完了後に仲介会社が登録し、成約価格、成約日、成約相手を含める。不成立の場合は理由を登録する。
- オークションが不成立で、オファーした買主と優先交渉へ進んだ場合も、同じ成約登録で結果を記録する。
- 成約価格はサイト内で取得し、外部だけに記録が残る状態にしない。

## 10. MVPで作らない機能

次の機能は今回の対象に含めない。

- AIによる査定や需要予測
- カウンターオファーを往復管理する専用機能
- 買主との自由な文章による交渉機能
- 複雑な金融機能
- 大規模な外部システム連携
- 全国一斉展開を前提とする機能
- 融資審査結果書類の登録
- サイト内での仲介、契約、決済

## 11. 本番開発まで保留する事項と影響

以下は確定要件ではない。モックアップでは具体的な数値やサービス名を推測せず、必要な状態だけを表現する。

| 保留事項 | 決める時期 | 要件・画面への影響 |
|---|---|---|
| 同時に利用する人数、締切時間帯の監視、障害対応の当番 | 本番開発時 | 画面の種類は変えず、混雑時の処理能力、監視方法、運営の担当人数に影響する。 |
| 本人確認（KYC）、決済、通知に使う外部サービス | 本番開発会社の決定後 | モックアップでは「審査済み」「通知済み」などの状態だけを示す。サービス名、実際の連携方法、費用は決めない。 |
| オファー・入札・落札・成約データの保存期間 | 本番開発前に費用と運用を確認した後 | 履歴を表示・保存する要件は維持するが、削除日や長期保存の案内は表示しない。 |
| 写真・資料1ファイルあたりの容量 | 本番開発時 | 掲載件数の上限は確定済みだが、容量制限の数値と警告文は決めない。 |

## 12. 希望条件登録と待機ユーザー集計

- 会員情報と基本的な希望条件は、約1分で登録できる第1段階としてまとめる。
- 詳細条件は登録完了後の任意プロフィールとし、最初からすべてを必須にしない。各項目は自由入力ではなくプルダウンから選択する。
- 登録完了後は条件に合う物件が出品された際に通知することを案内する。
- ITTOは「どこで・何を・いくらで買いたいか」を会員単位で保持する。
- 仲介会社には個人情報を公開せず、エリア・物件種別・予算帯別の待機ユーザー数だけを見せる。

## 13. マイページからの確認

- マイページ上段には「お気に入り／入札予定／提出済みオファー／参加中の入札」を並べる。
- 「提出済みオファー」は「条件付きオファーを提出中」、「参加中の入札」は「オークションに参加中」と補足する。
- お気に入り物件、入札予定物件、参加中の入札物件は、マイページからそれぞれ別の一覧で確認できるようにする。
- 未確認のお知らせは右側のお知らせ欄へ集約し、そこからお知らせ一覧へ進めるようにする。
- 提出済みオファーは、マイページから自分が提出した価格、購入条件、補足、提出日時、掲載仲介会社とのメッセージを一度に確認できるようにする。

## 14. 物件ステータスと需要行動

- 公開する物件ステータスは「まもなく開始」「オークション中」「終了」とする。
- 「まもなく開始」の物件には、オークション開始までの日数を表示する。
- 買主の「お気に入り」と「入札予定に登録」は別の行動として記録し、件数も分けて集計する。
- 物件一覧と物件詳細の両方から、お気に入りと入札予定を登録できるようにする。
- 終了した物件の写真はグレーの網掛けで表示する。
- 「オークション中」は色付きのステータスマークで表示し、「まもなく開始」と区別する。
- オークション中の物件は、お気に入り数、入札予定者数、実際の入札数を別々に表示する。

## 15. オファー返信への追加コメント

- 買主はマイページのオファー確認から、掲載仲介会社が送ったオファーへの返信に追加コメントを送れるようにする。
- 追加コメントはメッセージ形式で時系列に表示する。
- 買主が送信した追加コメントには、相手の未読・既読を表示する。
- 新規の自由な交渉を始める機能ではなく、オファーへの返信に対する補足連絡として扱う。

## 16. ブラウザの戻る・進む操作

- ブラウザや端末の「戻る」「進む」で、モックアップ内の直前または次の画面と表示位置を復元できるようにする。
- ヘッダーには専用の戻るボタンを置かず、ブラウザ標準の操作へ統一する。
